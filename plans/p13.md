# 1. Starting evidence

## P11

The direct factorized 28-bit exact-valid-set predictor showed:

```text
question-dependent probability signal:
aligned set-NLL < within-dataset shuffled set-NLL
```

but decoded almost entirely ALL-ON.

## P12

The structured maximal-run boundary/operation head preserved the same type of probability-level question signal but collapsed even more strongly:

```text
150/150 validation masks = ALL-ON
60/60 execution masks    = ALL-ON
W→C                      = 0
C→W                      = 0
visual-layer reduction   = 0
```

The structured route geometry was also weak:

```text
mean segments   ≈ 14.1
median segments = 14
median segment length = 1 layer
```

Therefore:

> Do not continue output-head redesign in this action.

P12 rules out the simple hypothesis that replacing independent bit thresholding with the approved maximal-run segment representation is sufficient to solve the probability-to-decoding gap under the bounded matched setup.

# 2. P13 research question

The current predictor is **question-only**, while the target MCTS route is defined for an **image-query pair**.

P13 asks:

> **Is the missing visual context a major bottleneck for predicting useful input-specific binary visual-computation routes?**

The controlled comparison is:

```text
Question-only
vs
Image-only
vs
Image + Question
```

while keeping the route head, loss, labels, data split, training budget, weighting, and executor fixed.

This is an **input-information isolation experiment**, not a new routing architecture project.

---

# 3. Primary hypothesis

The working hypothesis is:

> A question may contain partial routing information, as shown by P11/P12 aligned-vs-shuffled set-NLL, but may not contain enough information to determine which visual computation is useful for a particular image.

Example intuition:

```text
"What color is the car?"
```

may require different visual-computation routes depending on whether the image contains:

* one large clear car;
* multiple small cars;
* occlusion;
* text-heavy content;
* high-resolution details.

The predictor currently cannot distinguish such cases if it only observes question text.

P13 tests this hypothesis directly.

Do not assume it is true.

# 6. P13-A — Audit available frozen visual features

Before implementing a new multimodal predictor, inspect the current Qwen2.5-VL inference pipeline and identify the cheapest existing visual representation available **before answer generation and before dynamic routing decisions**.

Prefer reusing a representation that the original MLLM already computes.

Candidate sources may include, in priority order:

```text
1. projected visual tokens entering the language decoder
2. vision-encoder output before the multimodal projector
3. a deterministic pooled summary of those tokens
```

Do not add a separate external vision model unless there is no usable existing representation.

Do not use:

```text

ground-truth answer

FULL correctness
MCTS route identity

```

as predictor features.

# 8. Keep the multimodal fusion minimal

Do not create a large new multimodal architecture.

Use the smallest reasonable extension of the existing POLAR-style predictor.

Preferred structure:

```text
Question tokens
    ↓
existing frozen Qwen3 text embedding path

Visual tokens / pooled visual features
    ↓
small frozen or trainable projection to predictor dimension

Then combine them using the existing predictor infrastructure
with the minimum additional fusion required.
```

Possible acceptable designs include:

```text
concatenate question and visual feature tokens
before the existing layer-query cross-attention
```

or another equivalently minimal fusion that keeps the same layer encoder.

Do not add:

```text
deep multimodal transformer
new memory module
cross-modal recurrent routing
new vision tower
RL policy
```

in P13.

Before implementation, write down the exact proposed fusion and why it is the smallest controlled change.

# 12. P13-C — Modality-shuffle diagnostic

This is a critical part of P13.

For each validation target sample:

```text
target = (image_i, question_i, V_i)
```

evaluate four conditions.

## Condition 1 — Aligned

```text
(image_i, question_i)
→ predictor
→ evaluate against V_i
```

## Condition 2 — Question shuffled

Keep the correct image but use another question from the same dataset:

```text
(image_i, question_j)
→ evaluate against V_i
```

with:

```text
j != i
same dataset
```

## Condition 3 — Image shuffled

Keep the correct question but use another image from the same dataset:

```text
(image_j, question_i)
→ evaluate against V_i
```

The shuffled image must not be the paired target image.

## Condition 4 — Both shuffled

```text
(image_j, question_k)
→ evaluate against V_i
```

using deterministic within-dataset permutations.

Freeze all permutations before inspecting metrics.

# 13. Interpretation of modality shuffle

The strongest desired pattern is:

```text
Aligned
<
Question-shuffled
Image-shuffled
Both-shuffled
```

for set-NLL, with corresponding improvements in complete-mask metrics.

Questions to answer:

```text
Does correct question information help?
Does correct image information help?
Does combining both help more than either alone?
```

Particularly important:

> **Does Image+Question improve top-1 complete-mask behavior, not only probability-level set-NLL?**

P11/P12 already showed that set-NLL improvement alone is insufficient.

# 17. Primary success criterion

P13 is successful only if visual information helps **decoded and/or executed routing**, not merely probability calibration.

## Gate A — visual information contains routing signal

Image+Question should outperform Question-only on held-out route prediction metrics.

## Gate B — multimodal signal survives decoding

Image+Question should materially reduce constant ALL-ON collapse and produce meaningful complete-mask diversity.

## Gate C — aligned multimodal input beats shuffles

The aligned pair should outperform image/question shuffled conditions.

## Gate D — useful execution

Strong preferred evidence:

```text
W→C > 0
```

with controlled:

```text
C→W
```

and some reduction in:

```text
mean VISUAL_ON < 28
```

## Gate E — not explained by image-only or dataset prior

Image+Question should provide value beyond simple image-only or constant/dataset-level routing if the final claim is image-query-conditioned routing.

# 18. Decision outcomes

Choose exactly one outcome.

## Outcome A — Multimodal input resolves a meaningful part of predictability

Use if:

```text
Image+Question > Question-only
aligned > shuffles
decoded masks become materially nonconstant
and bounded execution shows useful route selection.
```

Interpretation:

> The question-only predictor lacked information necessary for useful route selection.

Recommendation:

prepare a separate full matched multimodal-training plan.

Do not launch full training without explicit approval.

---

## Outcome B — More input information changes probabilities but not routes

Use if:

```text
Image+Question improves set-NLL
but complete-mask decoding remains nearly constant
or execution shows no useful routing.
```

Interpretation:

> P11/P12/P13 repeatedly show probability-level conditioning without deployable route selection.

Do not continue by stacking larger encoders or heads.

The next research decision should reconsider the training target/objective, for example route utility prediction/ranking rather than direct valid-mask generation.

Do not implement that pivot automatically.

---

## Outcome C — Image information provides little additional signal

Use if:

```text
Image+Question ≈ Question-only
and image shuffling has little effect.
```

Interpretation:

> Missing visual input is not the main bottleneck under the current representation.

Do not scale predictor training.

Revisit whether the MCTS valid routes are stably predictable from inference-time features at all.

---

# 19. Optional follow-up only if Outcome B occurs

Do not execute automatically.
