```text
POLAR-style duplicated valid-route BCE
vs

```

under the same POLAR-style question-conditioned predictor, same MCTS labels, same initialization, same max-50 valid-route supervision, and equal within-input route weights.

The P10 result must be treated as the starting evidence for this task.

# 1. P10 result that motivates P11

P10 showed:

```text
Duplicated BCE
→ every executed top-1 mask = ALL-OFF

Exact set-NLL
→ every executed top-1 mask = ALL-ON
```

On the 150 validation route sets:

```text
Constant ALL-OFF Hit@1       = 0.1333
Learned duplicated BCE       = 0.1333

Constant ALL-ON Hit@1        = 0.5733
Learned exact set-NLL        = 0.5733
```

The learned predictors therefore did not demonstrate input-conditioned route selection in the smoke.

Exact set-NLL was behaviorally safer:

```text
Duplicated BCE accuracy = 0.2222
Exact set-NLL accuracy  = 0.5000
FULL accuracy           = 0.5000
```

but exact set-NLL achieved this by reproducing the constant ALL-ON behavior and full compute.

Therefore:

> **Do not launch the full matched training yet.**

The goal of P11 is to determine whether the constant mode is mainly caused by the valid-route geometry / objective preference for FULL, or whether the current question-conditioned factorized predictor still fails to learn useful input-dependent routing after applying the closest POLAR-compatible preference.

---

# 2. P11 high-level question

Answer the following question with the smallest bounded experiment possible:

> **If we apply POLAR-style down-weighting of the original/full route when a lower-compute valid route exists, does exact valid-set NLL begin to learn genuine input-conditioned non-constant route selection?**

The task consists of five stages:

```text
P11-A  Label-geometry audit
P11-B  Input-independent baseline audit
P11-C  POLAR-weighted matched smoke
P11-D  Input-dependence diagnostics
P11-E  Bounded real execution and go/no-go decision
```

Do not expand beyond these stages.

## 3.1 Constant-route coverage

```text

fraction of inputs where ALL-OFF ∈ V_x
```

where:

```text
ALL-ON  = 28 VISUAL_ON bits

```

Compute:

```text
fraction of inputs where:
ALL-ON ∈ V_x
```

It measures how often exact set-NLL can satisfy the valid-set objective through ALL-ON even though a cheaper valid route exists.

## 3.3 Valid-set sparsity statistics

For every input report/summarize:

```text
|V_x|
minimum VISUAL_ON count among valid masks
median VISUAL_ON count

```

## 3.4 Most common complete masks

Count complete 28-bit masks across valid sets.

Report:

```text
top-10 most frequent masks
fraction of inputs covered by each
```

Do not only count raw mask occurrences; also report per-input coverage:

```text
mask m is counted once for input x if m ∈ V_x
```

## 3.5 Best constant route

Find the single complete mask with maximum validation valid-set coverage:

```text
m_global*
=
argmax_m P_x[m ∈ V_x]
```

Report its Hit@1-equivalent coverage.

Do the same per dataset:

```text
m_GQA*
m_TextVQA*
m_ChartQA*
```

This is stronger than only comparing ALL-ON and ALL-OFF.

## 3.6 Valid-set overlap / route diversity

Use a simple deterministic statistic such as:

```text
pairwise valid-mask overlap
or
coverage of top-N global masks
```

Avoid expensive all-pairs computation if unnecessary.

The goal is to determine whether a small number of constant masks already explain most valid sets.

## P11-A interpretation

At the end, explicitly answer:

```text
Is ALL-ON a particularly strong global valid-set mode?
```

# 4. P11-B — Input-independent predictor baselines

Before evaluating a question-conditioned predictor, construct extremely small baselines that cannot use question information.

These are necessary to determine whether apparent route learning is actually only a global or dataset-level prior.

## 4.1 Global bias-only predictor

Implement a predictor with only:

```text
28 trainable logits
```

shared by every input.

There is no input encoder and no question dependence.

For exact set-NLL:

```text
P(m)
=
product_l Bernoulli(m_l ; p_l)
```

and optimize the same valid-set loss used by the real predictor.

For duplicated BCE, if inexpensive, train the corresponding matched bias-only baseline under the duplicated objective as well.

## 4.2 Dataset-conditioned bias-only predictor

Implement:

```text
3 × 28 trainable logits
```

one 28-logit vector each for:

```text
GQA
TextVQA
ChartQA
```

No question representation is allowed.

This baseline answers whether dataset identity alone explains the apparent routing signal.

## 4.3 Match training conditions

Use the same:

```text
training split
valid-mask cap
route weights
optimizer family
epoch budget
checkpoint rule
```

as the corresponding main predictor wherever applicable.

These models are tiny; do not over-tune them.

# 6. POLAR-compatible weighting rule

For every input `x`, start with:

```text
w_m = 1.0
```

for every selected valid mask.

If:

```text
ALL-ON ∈ V_x
```

and there exists at least one other valid mask with:

```text
VISUAL_ON_count(m) < 28
```

then set:

```text
w_ALL-ON = 0.3
```

while all other valid masks remain:

```text
w_m = 1.0
```

This is intended to mirror POLAR's released convention:

> when a shorter valid program exists, down-weight supervision from the original full-depth path.

Here:

```text
original full path ↔ ALL-ON
shorter program    ↔ valid mask with fewer VISUAL_ON layers
```

Do not introduce any other compute-aware weighting.

Do not use:

```text
exp(-beta * compute)
VISUAL_ON penalties
sparsity regularization
entropy bonuses
RL rewards
```

in P11.

# 7. Weight handling for the two objectives

The same relative route weights must be used for both objectives.

## Duplicated BCE

For each duplicated valid-route example:

```text
loss_i = route_weight_i * BCE(mask_i)
```

Preserve per-input normalization if required so that inputs with many valid masks do not dominate training.

## Exact valid-set NLL

Use:

```text
L(x)
=
-log Σ_{m ∈ V_x} w_m P_theta(m | x)
```

with the same relative route weights.

If weights are normalized within each input, document the exact normalization.

Do not create an objective mismatch between the two methods.

# 9. P11-D — Direct input-dependence diagnostics

A predictor should not be called input-conditioned merely because its architecture consumes the question.

We need evidence that changing the question changes useful route predictions.

Perform all tests on held-out validation data.

## 9.1 Compare against global bias-only predictor

For each objective, compare:

```text
question-conditioned predictor
vs
global bias-only predictor
```

using:

```text
Hit@1
Hit@5
nearest-valid Hamming
common set-NLL
```

The question-conditioned model must outperform the global prior to claim route predictability.

## 9.2 Compare against dataset-conditioned bias-only predictor

Compare:

```text
question-conditioned predictor
vs
dataset-conditioned bias-only predictor
```

This determines whether the model learns more than:

```text
"GQA tends to use route A"
"TextVQA tends to use route B"
```

## 9.3 Within-dataset question shuffle

Create a deterministic within-dataset permutation of validation questions.

For target sample `i`, replace its question representation with another sample `j` from the same dataset while evaluating the resulting predicted program against target valid set `V_i`.

Do not change:

```text
dataset identity
target valid set
evaluation target
```

Compute:

```text
Aligned-input Hit@1
Shuffled-input Hit@1

Aligned-input set-NLL
Shuffled-input set-NLL

Aligned nearest-valid Hamming
Shuffled nearest-valid Hamming
```

If predictions are truly question-conditioned, aligned input should outperform shuffled input.

If:

```text
Aligned ≈ Shuffled
```

then the model has not demonstrated meaningful question-specific routing.

## 9.4 Prediction diversity

Report:

```text
number of unique predicted masks
top-1 mask frequency
top-5 most common predicted masks
per-dataset mask frequency
```

A model that always predicts one mask has not passed the input-conditioning gate even if that mask has good valid-set coverage.

> **Does POLAR-weighted exact set-NLL learn input-dependent route selection beyond strong constant and dataset-only priors?**

# 12. Full-training admission gate

Do not launch full training automatically.

Full matched training is allowed only after explicit user approval and only if P11 provides credible input-dependent routing evidence.

The preferred admission criteria are:

## Gate A — Non-constant behavior

The exact-set predictor must not collapse almost entirely to:

```text
ALL-ON
ALL-OFF
or another single global mask
```

There must be meaningful top-1 route diversity.

## Gate B — Beat input-independent baseline

Question-conditioned exact set-NLL must outperform the **best global bias-only baseline** on held-out route-level metrics.

Preferably it should also outperform the dataset-conditioned bias-only baseline.

## Gate C — Aligned beats shuffled

Within-dataset aligned inputs must perform better than shuffled inputs on at least one primary route-level metric without materially worsening the others.

Preferred evidence:

```text
aligned Hit@1 > shuffled Hit@1
and/or
aligned set-NLL < shuffled set-NLL
```

## Gate D — Actual execution shows nontrivial routing

On the bounded real execution:

```text
predicted masks must not all be ALL-ON
average VISUAL_ON < 28
```

and there should be at least some evidence of useful route selection.

Strong preferred evidence:

```text
FULL-wrong → correct > 0
```

without an unacceptable increase in:

```text
FULL-correct → wrong
```

## Gate E — Exact remains better than duplicated

The exact objective should retain a plausible advantage over duplicated BCE in route-level or actual-execution behavior.

# 13. Decision outcomes

At the end of P11 choose exactly one of the following.

## Outcome A — Proceed to full matched training

Use only if:

```text
POLAR weighting breaks the constant mode,
question-conditioned exact set-NLL beats strong constant priors,
aligned > shuffled,
and bounded execution shows useful nonconstant routing.
```

Recommend full matched training, but do not launch it without explicit user approval.

## Outcome B — Objective shortcut remains

Use if:

```text
exact set-NLL still collapses to ALL-ON or another global route
and question-conditioned performance ≈ bias-only / shuffled performance.
```

Do not full-train.

Then run one final bounded diagnostic restricted to samples where:

```text
ALL-ON ∉ V_x
```

to determine whether the architecture can learn routes when the ALL-ON escape mode is impossible.

Do not run that diagnostic automatically unless needed to reach the P11 decision and it remains within the bounded scope.

## Outcome C — Input signal exists but factorized top-1 remains poor

Use if:

```text
aligned > shuffled
and
question-conditioned > bias-only
```

but actual top-1 masks still form poor uncached hybrids or execute badly.

Interpret this as evidence that:

```text
the valid-set objective is learning input signal,
but the factorized 28-bit head may be the next bottleneck.
```

Do not redesign the head during P11.

Prepare a separate architecture-pivot proposal.
